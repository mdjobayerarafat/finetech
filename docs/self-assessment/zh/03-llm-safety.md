# 3. 大模型安全边界

> English: [03-llm-safety.md (EN)](../03-llm-safety.md)

大模型是规划者,不是权威。不可妥协的架构规则:

1. **仅结构化输出。** 大模型输出 `proposed_actions[]` —
   类型化的工具调用与参数。它不输出金额、余额或"已完成"状态。
2. **服务端 schema 校验。** 每个工具调用都在服务端按
   `ToolSpec::arguments_schema` (JSON Schema) 重新校验。
   缺失或多余字段→动作被拒,而不是被默默强制。
3. **收款方重新解析。** 每个收款方、账户、商户都在工具内部
   针对数据库重新解析。大模型给出的 `payee_id` 或
   `account_id` 永远不被直接信任——而是按手机尾号、显示名
   或别名查找。
4. **不泄露秘密。** 大模型永远拿不到用户的密码、OTP、完整
   账号。它可以请求用户确认,但无法绕过。
5. **工具白名单。** 只有 `tools::registry()` 中的规范化名
   可被分发。其他一律被静默丢弃。管理员的 `forbid_tool`
   规则进一步按用户收窄。
6. **固定系统提示。** 系统提示固定且带版本号。管理员
   "引导前缀"是唯一的运行时注入点,且是**追加**的
   (它不能移除系统规则)。

这些由以下测试强制:

- `tests/security_*.rs` — 策略与规划器的直接集成测试。
- `redteam.test` 工具 — 用构造好的提示端到端测试大模型
  (见 [§2.3](./02-audit.md#23))。
