# 0. 范围说明

> English: [00-scope.md (EN)](../00-scope.md)

## 包含在本评估中

- **权限分级的实现** — 绿 / 黄 / 红 的决策流、升级规则、每个工具
  的分类。
- **每日限额与 `forbid_tool` 机制** — 在规划器内评估的、
  管理员可配置的规则。
- **审计哈希链** — 写入什么、如何校验、完整性端点暴露什么。
- **模拟 MFA 验证** — 进程内 `MFA_DEMO_CODE` 路径及其局限。
- **会话与 CSRF 处理** — cookie 属性、`X-CSRF-Token` 信封、
  安全锁。
- **提示注入防御** — 固定系统提示、结构化 `proposed_actions`
  信封、服务端参数重新解析。
- **已知风险与残余攻击面** — 诚实的清单(R-1 到 R-15)与
  今日**未**防御的部分。

## 不在范围内

- 通用产品 UX、演示脚本打磨、大模型的质性回答。
- 完整的 STRIDE 威胁模型 — 那个在
  [`../../THREAT_MODEL.md`](../../THREAT_MODEL.md)(在本文中引用;
  本构建版本尚未撰写)。
- 性能、扩展性、成本分析。

## 给审核者的重要背景

FinTech Pioneers 是一个**演示平台**。没有真实银行、真实卡片、真实资金。
每一次"转账"都只是 Postgres 里的一行记录,每张"卡"都只是
`cards` 表里的一行。本文档中描述的安全控制是按"如果这是真账本
也要能挡住攻击"的标准来设计的,但其中多个密码学与运维层面的
原语被有意简化,以便演示不需要金库、HSM 或短信服务商。每一处
都在 [§4 — 已知风险](./04-known-risks.md) 中明确列出。

> 这段背景是下面每条主张的框架。被标为"演示可接受"的风险
> 意味着*对一次受控的、刚搭好的演示可接受*;标为"生产不可接受"
> 意味着*在本平台承载真实客户资金之前必须关闭*。

## 如何阅读

每页结构相同:

- 一段简短的框架说明。
- 必要的表格与代码引用。
- 风险条目: **风险 → 状态 → 加固路径** 三段式,顺序固定,这样
